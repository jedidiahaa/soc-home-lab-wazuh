# Analyst note: rule 60204, Multiple Windows Logon Failures

## Summary

- Alert: Wazuh rule 60204, level 10, MITRE T1110 (Brute Force).
- Host: win-victim (Windows 11 Enterprise LTSC evaluation VM, hostname DESKTOP-I4CMLJC).
- Fired: 2026-10-31 12:37:48 UTC.

## What happened

Eight failed logons (event 4625, record IDs 2549 to 2556) for the local account `testuser` between 12:37:38 and 12:37:46 UTC. Windows then locked the account (event 4740, Wazuh rule 60115, level 9). Source address `::1` (the machine itself), logon type 2, process `svchost.exe` with logon process `seclogo` (the Secondary Logon service), started by the local account `labadmin`. Status `0xC000006D` with sub-status `0xC000006A`: the account exists and the password was wrong.

## How I confirmed it

- Expanded the alert in the dashboard and read the eight contributing events in `previous_output`.
- Counted 4625 events in the VM with `Get-WinEvent`: 1 before the test, 11 after.
- Found the lockout event 4740.
- Searched the last 200 successful logons (event 4624) for `testuser`: none found.

## Verdict

True positive, benign. I generated the attempts myself with a script against a throwaway account in my own lab.

## What I would do next if this were real

1. Find out what started the attempts. This lab has no process-creation logging, so I could not answer it.
2. Check for a successful logon (4624) for the account after the failures.
3. Review other activity by `labadmin` around that time.
4. If it was not authorised: disable and reset the account, isolate the host and escalate.
