# Custom rule 100101: raise severity when the audit log is cleared

**Status: deployed on 2026-11-13 and fired in two live tests. The MITRE fields appear after switching to the older ID T1070.001.**

## Why

Built-in rule 63103 ("The audit log was cleared", event 1102) fires at level 5. Clearing the Security log is a typical way to hide tracks, so I think it deserves a higher level than a routine account alert.

## Draft (my own)

- ID: 100101
- Level: 12. The same level as the built-in Administrators group change. On the dashboard overview, levels 12 to 14 count as High severity.
- Parent rule (`if_sid`): 63103, the built-in "The audit log was cleared"
- Description: Windows audit log cleared: possible attacker covering tracks (my first wording was "possible attacker clearing tracks". I changed it to state the fact first and keep the hedge)
- MITRE: T1070.001 (Clear Windows Event Logs). In the current ATT&CK matrix this technique is T1685.005, which is what I used first. Wazuh 4.14.9 attached no MITRE fields for it, so I switched to the older ID T1070.001 that its database knows.

## Why level 12

Clearing the Security log is a typical way to hide tracks, and the built-in alert is only level 5.

## False positives

Administrators sometimes clear logs on purpose (maintenance, imaging a machine). So a level-12 alert needs a quick check of who ran it.

## Test result

- Test: `wevtutil cl Security` on `win-victim`, own VM, 2026-11-13.
- Result: rule 100101 fired at 13:53:39 Budapest time (12:53:39 UTC), level 12. The underlying event was Windows event 1102 (audit log cleared) at 12:53:38 UTC. `rule.firedtimes` was 1.
- 63103 did not fire again for this event. The only 63103 alert in the list is the earlier one from 13:20:57. This is consistent with a child rule replacing its parent for that event.
- `rule.mail` was `true` at level 12, whereas the level 8 and level 10 alerts earlier showed `false`. Level 12 appears to be where Wazuh marks an alert for email. No mail server is set up in this lab, so nothing was sent. I have not checked the email alert level in the manager's config.
- **MITRE fields were missing.** The 100101 alert shows no `rule.mitre.*` fields, whereas the 100100 alert showed id, tactic and technique. My explanation, not yet proven: Wazuh 4.14.9's built-in ATT&CK database does not know the new ID T1685.005, so it attached nothing. Supporting evidence: Wazuh's own rule 63103 is tagged T1070, the older numbering.
- **Second test, after switching to T1070.001:** cleared the log again. The new alert at 13:59:20 Budapest time (event 1102 at 12:59:19 UTC) shows `rule.mitre.id` T1070.001, tactic Defense Evasion, technique Clear Windows Event Logs. The 13:53:39 alert from the first test still shows no MITRE fields. Both stay in the alert list, which shows the before and after.
